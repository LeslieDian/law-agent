## 1. 4b-0：检索库范围门禁

### 1.1 为什么要设这道门禁

论文 3.3 / 3.4 把**裁判文书**作为向量化对象（入口 = `Case` 节点，`Case.embedding` 存 Neo4j），
而阶段 4 的 `train` / `dev` / `test` / `router` 四份 split **也都来自同一批案件语料**。
若评测样本进了检索库，模型就是**对考题开卷检索** → 全部 RAG 指标作废。

### 1.2 实测：四份 split 的关系（独立复核阶段 4）

| split | 行数 | 唯一 uid |
|---|---:|---:|
| train | 100,000 | 100,000 |
| dev | 1,000 | 1,000 |
| test | 1,000 | 1,000 |
| router | 20,000 | 20,000 |

- **两两交集最大值 = 0**（六对组合全部为 0，与阶段 4 的 C3 结论一致）
- **评测集（dev ∪ test ∪ router）唯一 uid = 22,000**

> ⚠️ `data/train/` 下的 `civil.jsonl`(40,000) / `criminal.jsonl`(30,000) / `procedure.jsonl`(20,000) /
> `general.jsonl`(10,000) 是 `train.jsonl`(100,000) 的**按域视图**，不是额外样本
> （40,000+30,000+20,000+10,000 = 100,000）。`dev` / `test` 同理。统计时切勿重复计数。

### 1.3 ★ 核心发现：评测样本全是「案件类」，不设门禁必泄漏

清洗后 qa 语料 270,989 条的 `task_kind` 分布与评测集交叠：

| task_kind | 条数 | 落在评测集内 |
|---|---:|---:|
| `case_analysis` | 146,346 | **11,811** |
| `qa` | 98,384 | 7,971 |
| `exam` | 25,842 | 2,176 |
| `concept` | 417 | 42 |
| **合计** | **270,989** | **22,000** |

**评测集 22,000 条 100% 落在 qa 流里**，其中**案件分析类独占 11,811 条（53.7%）**。
这直接量化了「不做门禁的后果」：**近 1.2 万条评测样本会进入检索库**。

法条流 `statute_items` 65,037 条与评测集交叠 **0**（跨流，天然隔离）。

### 1.4 检索库候选范围（三种口径）

源池 = 清洗后 qa（270,989）∪ statute_items（65,037）；`case` = `task_kind == case_analysis`。

| 方案 | 与哪些 split 隔离 | 总量 | 其中 qa | 其中法条 | 其中案件类 |
|---|---|---:|---:|---:|---:|
| **A（推荐）** | 与**四份全隔离** | **217,026** | 151,989 | 65,037 | 82,821 |
| B | 只与评测集隔离（train 可入库） | 314,026 | 248,989 | 65,037 | 134,535 |
| C | 仅案件类，与四份全隔离 | 82,821 | 82,821 | 0 | 82,821 |

### 1.5 定案：检索库 = 案件文书 + 法条条文（双 collection）

采用**方案 A 的强隔离口径**，并按其用途拆两个 collection：

| collection | 内容 | 条数 | 论文对应 |
|---|---|---:|---|
| `case_embedding` | 案件文书（`task_kind = case_analysis` 且不在四份 split 内） | **82,821** | 3.3 / 3.4 的 `Case` 节点 |
| `provision_embedding` | 法条条文（`statute_items` 全部） | **65,037** | `retrieval.yaml` 的 `provision_*` 索引 |
| **合计** | | **147,858** | |

**不收进检索库的**（登记为后备池，不入库）：

- 非案件类 qa 样本 **69,168** 条（= 方案 A 的 qa 部分 151,989 − 案件类 82,821，已扣除评测集与 train）
  —— 它们是「问答对 / 考题」，不是裁判文书；且 `exam` 类与评测任务同质，
  入库后可能**检索出题目本身**，反而制造泄漏。
- `train` 的 10 万条 —— 训练语料不应同时充当检索库，否则评测时模型可能检索到自己见过的样本。
  （其中 97,000 条来自 qa 流、3,000 条来自 procedural 派生）
- `derived`（13,484 条派生任务）—— 合成训练数据，不是知识。

**验收断言（已 PASS）**

## 2. 4b-1：法名规范化（H4 更正）

### 2.1 问题：同一个法，两种写法，图谱会被撕成两半

`:Law`（法名层）节点的自然键是法名，但语料里存在**两级**写法差异，必须**两级都归一化**：

| 级别 | 处理 | 针对的差异 | 来源 |
|---|---|---|---|
| **L0 → L1** | 剥书名号 `《》` + 去空白 + 统一括号 | **跨源**：pandalla 全部带《》，twang2218 不带 | 两个数据集风格不同 |
| **L1 → L2** | 再剥**版本标记**后缀（`(2019修正)` / `（2020年修订）` / `[2018修改]`） | **同源多版本** | 同一部法有多个版本条目 |

> ⚠️ **更正 H4 的原记述**：此前记为「未规范化 1,807 vs 规范化 1,579，**228 个书名号造成的重复**」。
> 数字 228 是对的，但**归因只对了一半**：228 = **80（书名号）+ 148（版本后缀）**。
> 只剥书名号只能消掉 80 个，还剩 148 个影子节点。

### 2.2 实测：两级归一的逐级效果

| 流 | 行数 | L0 raw 唯一 | L1 唯一 | **L2 唯一** | 跨源 raw 交集 | L1 交集 | **L2 交集** |
|---|---:|---:|---:|---:|---:|---:|---:|
| `statute_items` | 65,037 | 1,807 | 1,727 | **1,579** | **0** | 80 | **228** |
| `statutes`（去污镜像全量） | 22,771 | 17,429 | 17,347 | 17,198 | **0** | 80 | 229 |

并集自洽验证（items）：
- `1,807 → 1,727`：跨源书名号合并 **80** 个（1,548 + 259 − 80 = 1,727）
- `1,727 → 1,579`：再剥版本后缀合并 **148** 个（1,548 + 259 − 228 = 1,579）
- **合计 228** ＝ H4 登记的合并数 ✓

**核心结论**：如果不做两级归一化，两个来源的法名在**字符串层面交集为 0** ——
建图后会生成两套互不相连的「影子 Law 节点」，图谱被撕成两半。
归一化后能连上 **228 个法**（这 228 个正是「被多个源文件共享的 L2 法名」）。

### 2.3 为什么 `statute_items` 只有 1,579 个法名而 `statutes` 有 17,198 个

**不是数据缺口，是阶段 2b 的设计**（见 [`STATUTE_SPLIT_REPORT.md`](STATUTE_SPLIT_REPORT.md) 第 1 节）：

| 类型 | 源文档数 | 处置 |
|---|---:|---|
| 地方性法规 | 19,152 | ❌ 丢弃（非国家级规范） |
| 修改、废止的决定 | 649 | ❌ 丢弃 |
| 有关法律问题和重大问题的决定 | 169 | ❌ 丢弃 |
| 宪法 | 6 | ❌ 丢弃 |
| 监察法规 | 1 | ❌ 丢弃 |
| 司法解释 / 行政法规 / 法律 / 法律解释 | 740+663+382+25 = **1,810** | ✅ 保留并切条 |

保留 1,810 部 → L2 去重后 **1,579** 个法名（差额 231 来自版本后缀变体与跨源同名）。
`statutes` 流是**去污镜像**，保留全量 22,771 部，两流口径本就不同。

> **检索库的「法条」部分取 `statute_items` 的 65,037 条**（国家级规范，已切到条级），
> **不是** `statutes` 的 22,771 部整篇法规（粒度过粗，且含地方性法规）。

### 2.4 高频法名（L2 口径，items）

| 条数 | 法名 |
|---:|---|
| 1,654 | 最高人民法院关于适用《中华人民共和国民事诉讼法》的解释 |
| 1,200 | 最高人民法院关于适用《中华人民共和国刑事诉讼法》的解释 |
| 692 | 人民检察院刑事诉讼规则(试行) |
| 684 | 人民检察院刑事诉讼规则 |
| 652 | 中华人民共和国民用航空法 |

> 注意 `人民检察院刑事诉讼规则(试行)` 与 `人民检察院刑事诉讼规则` **是两条独立法名** ——
> 「(试行)」是**实质后缀**，表示不同的规范文本，规范化时**刻意不合并**（只剥版本标记）。

### 2.5 规范化规则（写入代码，供建图复用）

```python
VER_SUFFIX = re.compile(
    r"[（(\[][^（）()\[\]]{0,30}?(?:修正|修订|修改|废止)[^（）()\[\]]{0,30}?[)）\]]\s*$")

def strip_wrappers(t):      # L1：剥任意层书名号 + 去空白 + 括号全角转半角
def strip_version(t):       # L1 + 剥版本后缀，循环到稳定
```

**刻意不做的事**（会改变法的身份）：
- ❌ 不合并「（试行）」等实质后缀
- ❌ 不增删「中华人民共和国」前缀
- ❌ 不做「XX法实施条例」→「XX法」之类的语义归并

### 2.6 一个数据形态备注

`statutes` 流里有 **2 条** pandalla 的**条级**记录没有 `law_title`
（`uid = pandalla__chinese_law_examples__law_item:998 / :999`，`source_id = -998 / -999`）——
它们是 pandalla 的「条级源」混入 `statutes` 流，源侧就没有法名。
**不影响 `statute_items`**（其 pandalla 982 条均有法名）。已在报告中登记，不阻断流程。
