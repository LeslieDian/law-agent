## 1. 绝对禁止进入训练/验证集的内容

- [ ] 254 个 CLaw 案例的**题目**
- [ ] 254 个 CLaw 案例的**参考答案**
- [ ] 对上述案例自动生成的**改写版本**（同义改写、换问法、增删细节均算）
- [ ] Judge 模型对这些案例生成的**评分解释 / 理由文本**

> 上述四类内容一旦进入训练集，E1/E4/E5 的成绩即不可信。

## 2. 四级查重（训练集 vs CLaw 测试集）

按顺序执行，任一级命中即人工复核：

| 级别 | 方法 | 判定 |
|---|---|---|
| L1 | 完全字符串比对 | 命中 → 直接剔除 |
| L2 | 去标点、去空格、统一全半角后比对 | 命中 → 直接剔除 |
| L3 | MinHash + LSH 近似查重（`datasketch`） | Jaccard > 0.85 → 人工检查 |
| L4 | 向量相似度（BGE-M3 嵌入） | 余弦 > 0.92 → **人工检查** |

查重脚本：`src/prepare/check_leakage.py`，输出报告落盘到 `reports/leakage_report.md`。

## 3. 数据切分规则

| 分区 | 比例 | 说明 |
|---|---|---|
| 训练集 train | 90% | |
| 验证集 dev | 5% | |
| 内部测试集 test | 5% | 仅用于内部选 checkpoint |

**必须按案件来源（case source）分组切分，而不是按单条样本随机切分。**
同一案件派生出的多个问题必须落在同一分区。

**CLaw 的 254 个案例不进入任何一个训练 / 验证 / 内部测试分区。**

## 4. 法条库的两种实验边界

| | 闭卷实验 | RAG 实验 |
|---|---|---|
| 允许检索数据库 | ❌ | ✅ |
| 适用实验 | E0、E1 | E2、E3、E4、E5 |
| 用途 | 与 CLaw 官方模型结果比较 | 验证系统实际应用能力 |
| 论文表述 | 可直接比较 | 必须注明"增强条件" |

## 5. 训练数据必须包含的"困难样本"

只有正例的训练数据会教出"永远自信地编法条"的模型。必须包含：

- [ ] 正确版本的法条引用（含历史版本场景）
- [ ] 引用不存在时的**拒答**
- [ ] 证据不足时的**谨慎回答**
- [ ] 新旧法律版本冲突的处理
- [ ] 条文相似但编号不同的**负样本**
- [ ] 错误法条纠正样本

## 6. checkpoint 选择纪律

> **只能用内部验证集选最佳 checkpoint，选完以后再运行 CLaw。禁止用 CLaw 挑 checkpoint。**
