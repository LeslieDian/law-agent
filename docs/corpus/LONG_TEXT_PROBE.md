> 生成时间：2026-09-19　探查对象：`data/corpus/statute_items/`（65,037 条 = item 64,700 + doc 337）
> 脚本：[`../../scripts/corpus/probe_long_text.py`](../../scripts/corpus/probe_long_text.py)（只读，不写文件、不改语料）
> 用途：在 **4b-3 向量化之前**判定两件事 ——
> **H6** item 最长 26,980 字是「切条遗漏」还是「该条本身很长」；
> **H5** doc 级 337 条（最长 61,387 字）是什么内容、能否与 item 同池做语义检索。

## 1. 结论（先看这个）

| 问题 | 结论 |
|---|---|
| **H6 切条遗漏？** | **否**。判据：item 正文**行首**出现 ≥2 个条号的记录 = **0 条**（质检 C3 已保证行首无残留条号）。 |
| 那 26,980 字是什么？ | **司法解释第十二条所附的「数量认定标准表」** —— 一张 667 个换行的 ASCII 表格，不是未切开的整篇。 |
| **H5 doc 级** | 全部来自 `twang2218`（337 条 / 325 个不同法名），**86.4% 是司法解释**（291/337）；最长那条是「行政审批项目目录」附件。 |
| 处置成本 | **不需要重跑阶段 2b**。只需在向量化时对 **35 + 337 = 372 条（占 0.57%）** 做单独处置。 |

## 2. H6 判据与结果：无切条遗漏

判据设计：若某条把「多条」塞进了自身正文，那么它的正文里**行首**应当出现多个条号。

```
ART_LINE = r'^\s*第\s*[0-9一二三四五六七八九十百千零〇]+\s*条'
命中条数 = 0
```

⇒ **没有一条 item 包含第二个行首条号**，切条是干净的。
（最长 20 条 item 的「行首条号数」全部为 0，说明条号前缀在切条时已剥离并存入 `article_label` 字段。）

## 4. 最长样本的真实内容（决定性证据）

**最长 item（26,980 字）**

- `law_title`：最高人民法院关于审理破坏野生动物资源刑事案件具体应用法律若干问题的解释
- `article_label`：第十二条　`char_len`：26,980（与 `len(text)` 一致）
- 换行数：**667**；正文开头即为 ASCII 表格：

```
单位犯刑法第三百四十一条规定之罪,定罪量刑标准依照本解释的有关规定执行。
附:
非法猎捕、杀害、收购、运输、出售珍贵、濒危野生动物刑事案件"情节严重"、"情节特别严重"数量认定标准表
+-------------+-------------+-------------+-------------+-------------+
| 中文名      | 拉丁文名    | 级别        | 情节        | 情节特      |
...
| 蜂猴        | Nycticebus  | I           | 3           | 4           |
```

⇒ 这是**该司法解释第十二条自身附带的一份物种认定表**（数百行 `+----+` 边框表格）。
**内容真实、切条无误**，但它**不是语义文本**，不适合做语义检索单元。

**最长 doc（61,387 字）**

- `law_title`：国务院对确需保留的行政审批项目设定行政许可的决定
- 换行数：**1,512**；正文含「附件：国务院决定对确需保留的行政审批项目设定行政许可的目录」+ 500 项清单表。

⇒ 同类问题：**长 doc = 附件目录 / 清单 / 表格**，而非长篇论述。

**超长样本的 `law_type` 分布**（不集中，各种类型都有）

| 阈值 | 条数 | 分布 |
|---:|---:|---|
| > 1,000 字 | 35 | 法律 11 / 行政法规 9 / 司法解释 9 / 法律解释 3 / pandalla 类别标注 3 |
| > 3,000 字 | 9 | 行政法规 4 / 法律 2 / 司法解释 2 / pandalla 1 |

⇒ **不是某个来源的批量缺陷**，而是「部分法条本身含附表」这一法律文本的固有特征。

## 7. 对 4b-3 的处置（取代 `retrieval_design.md` 里 H5/H6 的原始描述）

**影响面：372 / 65,037 = 0.57%。** 不必重跑阶段 2b。

| 对象 | 条数 | 处置 |
|---|---:|---|
| item，> 1,000 字 | **35** | 建索引前做**表格剔除 + 截断**：检测 `+---`/`---` 连续行与「附表/附件/目录」标记；去表后若正文 < 200 字则**只入图谱、不入向量索引** |
| item，≤ 1,000 字 | 64,665 | 正常向量化 |
| doc 级 | **337** | **不与 item 同池**（单独 collection 或只入图谱）；若要嵌入，只嵌「法名 + 首段」，不嵌全文 |
| 长文本截断上限 | — | 建议按模型上限与句界截断（如 1,024 token），**截断前后都记录 `text_hash`**，保证可回溯 |

**为什么要单独处置**：极端长样本与 p50=91 字的常规样本同池时，`top-k` 会被少数长文本挤占
（向量长度归一化后长文本的「语义平均」更接近通用语义，容易与任意查询都算出中等相似度）。

## 8. 一句话给论文

> 法条语料中 **0.054% 的条目含附表/清单**（多为司法解释末条的认定标准表与目录），
> 本研究在向量化前对其做去表处理，并令无独立语义的目录类条目**只入知识图谱、不入语义索引**。
