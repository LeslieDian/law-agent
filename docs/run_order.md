# 执行顺序（按此顺序做，最省时间；不要一上来就训练模型）

## 阶段 A：数据与评测链路（不碰 GPU 也可推进）

1. **取得并校验 CLaw 数据** → 登记 `docs/data_manifest.json`，核对 306 / 64,849 / 254
2. **建立统一输出格式与评测脚本**（`src/evaluation/`）
3. **用原始 Qwen 跑 10 个案例**，验证端到端能跑通
4. **验证 Judge 评分流程**（双 Judge + 盲测 + JSON 解析）
5. **运行 E0 的 254 个案例** → 得到基础闭卷基线

## 阶段 B：知识层建设

6. 收集并清洗法律语料（保历史版本 + 生效/失效区间）
7. 建立 Neo4j 图谱 + 向量索引 + 全文索引（`docs/neo4j_setup.cypher`）
8. 建立 **50～100 题检索验证集**（人工标注 gold 条文）
9. 调通 向量召回 / BM25 / 时间版本过滤 / 重排序
10. **运行 E2、E3** → 检索指标先达标（Recall@5 ≥ 0.85，未达标先修检索，不要靠提示词掩盖）

## 阶段 C：训练

11. 清洗训练数据 + 跑 CLaw 泄漏排查（`check_leakage.py`）
12. **用 500 条数据试训 QLoRA**，检查模板 / assistant-only loss / 显存峰值
13. 完整训练统一法律适配器
14. **运行 E1 和 E4**

## 阶段 D：完整系统与消融

15. 加入知识图谱 + 适配器路由，**运行 E5**
16. 完成消融 A1～A5
17. 两个 Judge 独立评分
18. 统计置信区间与显著性（配对 Bootstrap）
19. 替换论文中的实验设计、公式与结果表
20. 保存数据版本、模型哈希、配置与全部原始输出
