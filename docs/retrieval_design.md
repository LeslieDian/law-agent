## 勘误（2026-09-19）：本设计的主体对象判断有误

本文第一版**只扫了阶段 2b 的法条切条产物（65,037 条）**，据此断言
「`:Case` 不建 —— 语料内无结构化案例字段」。**该结论错误**。

补扫 `data/corpus/normalized/qa/` 后实测（证据：[`corpus/CASE_PROBE.md`](corpus/CASE_PROBE.md)）：

| 项 | 实测 |
|---|---:|
| 案件正文类样本 | **154,920** |
| 去重后唯一案件 | **143,009** |
| 其中 `input >= 300`（真实案件正文） | **99,626** |
| 带案由（"XX纠纷"） | 40,851（41.0%） |
| 带日期 | 75,188（75.5%） |

**结论修正**：
1. `:Case` **可以建**（~99,626），且它才是**论文 3.2/3.3/3.4 设计的检索入口**
   （向量化对象 = 裁判文书，`Case.embedding` + Neo4j 内嵌向量索引）；
2. 本文把**法条（`Provision`）当作向量库主体**，与论文的主从关系不符 ——
   法条在论文里是**图谱节点 + 检索后的关系扩展对象**，不是第一入口；
3. 因此本设计**保留作为「法条侧的检索子设计」**（其数字均基于 65,037 实测，仍然有效），
   但**完整的检索层设计须以 Case 为主入口重写**，见待办。
4. 第 2.2 节「`:Case` 不建」与第 0 节「4 类无数据」的表述**作废**，
   子图实体的可实例化判定以 `corpus/CASE_PROBE.md` 第 5 节为准
   （17 类中 3 类可建 + 3 类弱可建 + 11 类无料）。

## 0. 结论速览

| 项 | 原设计 | 实测后改为 | 为什么 |
|---|---|---|---|
| 节点 | 7 类 | **5 类** | 4 类无数据，1 类与 Law 1:1 冗余 |
| 关系 | 8 类 | **5 类** | Case 相关 4 类无边可建 |

## 1. 实测依据（本设计的全部事实基础）

### 1.1 节点可派生性

| 节点 | 派生方式 | 实测数量 |
|---|---|---|
| `:Law` | `law_title` 剥外层书名号 + 剥版本后缀 + 去空白 | **1,579** |
| `:LawVersion` | 规范名 + (版本标记, publish_date) | **与 Law 1:1 → 无多版本** |
| `:Provision` | `level=item` | **64,700** |
| （doc 兜底） | `level=doc` | 337 |

⚠️ **`law_title` 必须先规范化**：未规范时 `distinct(law_title) = 1,807`，但两个源的**交集是 0** ——
pandalla 的 259 个法名**全部外层带书名号**（`《中华人民共和国高等教育法(2018修正)》`），
twang2218 的 1,548 个不带。字符串层面互不相识 → 会产生 **228 个重复的"影子 Law 节点"**。
规范化（剥外层书名号 + 剥版本后缀 + 去空白）后交集 228，并集 **1,579**，
即 **1,807 → 1,579，消掉 228 个重复节点**。

> 口径提醒：阶段 2b 报告的「1,810」是**保留的文档数**（740 司法解释 + 663 行政法规 + 382 法律 + 25 法律解释），
> 与 `law_title` 字符串数（1,548）不是同一口径（存在同名文档分卷的情况）。建 `Law` 节点以规范化后的 **1,579** 为准。

### 1.2 时间字段覆盖（决定 `time_filter` 能否成立）

| 字段 | 覆盖情况 |
|---|---|
| `effective_to` | **字段根本不存在（0 行）** |
| `effective_from` | **缺失 20,834 行（32.0%）** |
| `effective_period` | 有值 64,055 行，但格式是**十年粗区间**（如 `"2020_2030"`） |
| `publish_date` | 缺失 982 行（pandalla 全部） |
| `status` | 有效 46,810 / 已修改 12,547 / 已废止 4,635 / 未知 982 / 尚未生效 63 |

**结论**：`retrieval.yaml` 里的规则
`effective_from <= case_date AND (effective_to IS NULL OR effective_to > case_date)`
**没有字段可依** —— 缺 `effective_to`、缺 1/3 的 `effective_from`、`effective_period` 粒度是十年。
→ **A2 消融（去掉时间版本过滤）目前开了和关了没有区别**；`historical_version_accuracy ≥ 0.95` 这个目标当前不可评测。

### 1.3 检索粒度

| 项 | 实测 |
|---|---|
| `paragraph` / `article_sub` 非空行 | **0**（只有"条"级，没有款/项） |
| `article_no` 为空 | 337（= doc 级） |
| 章节标记 `chapter` | 29,945 行（46.0%） |
| `text` 长度（item） | p10 39 / p50 **91** / p90 219 / p99 426 / **max 26,980** 字 |
| `text` 长度（doc） | p10 206 / p50 472 / p90 2,292 / p99 14,854 / **max 61,387** 字 |
| 正文残留行首条号 | **0**（质检 C3 已保证） |
| `content_sha1` | 65,037 行全有 → 可直接作 `text_hash` |

⚠️ 实验矩阵表 2/3 里的「**条+款**」「**条+款+项**」两列，**当前语料无法填充**（款/项粒度为 0）。
⚠️ item 最长 26,980 字、doc 最长 61,387 字 → 与 p50=91 字**差三个数量级**，混在同一向量空间会污染检索。

### 1.4 关系可建性（图谱那一路的真实料量）

| 关系 | 构建来源 | 实测规模 |
|---|---|---|
| `(Law)-[:HAS_PROVISION]->(Provision)` | `law_title` 规范化后分组 | **64,700** |
| `(Provision)-[:NEXT]->(Provision)` | 同法内按 `article_seq` 排序 | **≈ 63,121**（64,700 − 1,579） |
| `(Provision)-[:CITES]->(Provision)` | 正文交叉引用抽取 | **≈ 4,072** |
| `(Case)-[:CITES]->(Provision)` 等 4 类 | 需要结构化案例 | **0（语料内无字段）** |

`CITES` 的抽取实测（限定在**实际入库的 64,700 条 item 正文**内）：

| 形式 | 出现次数 | 可解析到目标条文 |
|---|---|---|
| `本法第十二条`（同法内） | 3,820 | **3,755（98.3%）** |
| `《中华人民共和国刑法》第二百九十四条`（具名） | 504 | **252（50.0%）** |
| 无前缀的「第X条」（如"依照……的规定"） | 6,305 | 0（无法正则化） |
| **合计** | **10,629** | **4,007（37.7%）** |

> 旁证（全量口径）：22,771 部法规文档共 **124,868** 处非行首「第X条」（`ART_ANY 971,412 − ART_LINE 846,544`），
> 其中 `本法第Y条` 62,432 处、`《X法》第Y条` 3,332 处。按保留文档占比折算，与上表量级一致。

**关键推论**：`CITES` 边约 4 千条 → 在 64,700 条条文中，**只有约 6.3% 的条文有出边**。
以 `graph_expand_hops=1` 做扩展，能影响的查询不到 10% → **E2（纯向量）→ E3（+图谱+BM25）的主结论很可能跑不出显著差异**。

## 4. 检索链路落地要点（对齐 `configs/retrieval.yaml`）

### 4.1 向量路
- 4 路索引字段照原设计（`embedding` 1024 / `embedding_bge_m3` 1024 / `embedding_bert768` 768 / `embedding_qwen3_4b` 2560）。
- **换模型 = 全量重建**（不同模型向量不在同一空间），A5 消融每换一档就是一次全量重建，排期时按 4 次算。
- 存储估算：65,037 × 1024 × 4B ≈ 266 MB/路，4 路 + 索引约 1.2 GB，可接受。

### 4.2 关键词路（BM25）
- Neo4j 全文索引默认 analyzer 对中文**按字切**，BM25 质量一般。
- 二选一：① 给 `provision_fulltext` 配 CJK 分析器；② 外挂 `rank_bm25` + 自建倒排（可控性更好，且便于论文里解释分词方案）。
- **二选一必须写进论文实现细节**，否则复现者拿到的数字对不上。

### 4.3 图谱扩展路
- **主力换成 `NEXT`**：召回条文后沿 `NEXT` 取前后各 1 条（法条检索里"上下条"提供上下文，命中率增益稳定且覆盖 100% 条文）。
- `CITES` 只对"有出边的 6.3% 条文"生效，作为**辅助信号**而非主力。
- **必须加限流**：`max_expand_per_hit`（如 8）+ 按目标节点入度降权，否则热门条文（如刑诉法、公司法某条被引用数十次）会带来度爆炸。

### 4.4 融合（RRF 的坑）
- RRF 只能融合**有序列表**；图谱扩展输出的是**集合**，没有 rank。
- 处理：给扩展结果按图算法打分（`1/(1+hops)` × 边权），转成有序列表后再进 RRF；或改用加权分数融合。
- 这一步不做，图谱那一排在 RRF 里权重会被稀释成噪声。

### 4.5 时间过滤（降级方案）
```
status = '有效'  (现行)
status = '已废止' + 场景标注（历史版本问答）
```
`effective_from` 只在非空时参与排序微调，**不做硬过滤**（32% 缺失会导致误杀）。

## 5. 设计热点（按严重度）

| # | 级别 | 热点 | 实测证据 | 处置 |
|---|---|---|---|---|
| **H1** | 硬伤 | **时间版本过滤无数据**，A2 消融失效 | `effective_to` 0 行；`effective_from` 缺 32%；多版本 0；`effective_period` 是十年粗区间 | 降级为 `status` 过滤；A2 改为「有/无 `status` 过滤」；历史版本准确率目标下调或补数据源 |

| **H3** | 硬伤 | **图谱 `CITES` 稀疏**，E2→E3 可能不显著 | 可解析引用仅 4,007 处 → 覆盖 6.3% 条文 | 扩展主力改 `NEXT`（覆盖 100%）；`CITES` 降为辅助 |

| **H6** | 高 | **item 异常长条** | max 26,980 字（可能未切开的整篇） | 排查 top 20 最长 item，确认是否切条遗漏；确认后决定是否重切 |

| **H11** | 低 | `effective_period` 是十年区间，易被误当精确日期用 | 样例全为 `"2020_2030"` | 文档里明确标注语义，避免下游误用 |
